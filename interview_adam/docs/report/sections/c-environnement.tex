\subsection{Variables}

Le module ne lit la configuration que par l'intermédiaire de
\file{config\_adam.py}, qui applique une valeur par défaut à chaque variable :
\textbf{aucune} variable n'est obligatoire pour démarrer, à part le choix
contraire. Les valeurs par défaut ci-dessous sont celles du dépôt, relevées dans
\file{config\_adam.py} et \file{.env.example} --- pas celles d'un poste de
développement.

\subsection{Installation}

Les commandes sont celles utilisées sur le poste de développement (Python~3.14,
Windows). Elles supposent le dépôt de l'équipe cloné à la racine du projet.

\begin{lstlisting}[style=adamshell]
# 1. Environnement unique pour les deux modules (jamais deux versions du meme paquet)
python -m venv .venv
.venv\Scripts\activate
pip install -r requirement.txt
pip install -r interview_adam\requirements_interview_adam.txt
#    -> n'ajoute que faiss-cpu, pytest et httpx : torch, transformers, fastapi,
#       pydantic et requests viennent deja du fichier de l'equipe

# 2. Modele local
ollama serve                       # ecoute sur 11434
ollama pull mistral:7b-instruct-v0.2-q4_K_M
ollama list                        # verifier la taille reellement telechargee

# 3. Index documentaire (a relancer apres toute modification de knowledge/)
python -m interview_adam.rag.ingest
#    -> ecrit data/interview_adam/knowledge.faiss et knowledge_meta.json,
#       affiche le nombre de fragments par domaine (72 au total)

python -m interview_adam.rag.search "DevOps conteneurisation Docker pipeline"
#    -> outil de demonstration : top-k avec scores, sans passer par le modele
\end{lstlisting}

\subsection{Démarrage}

\begin{lstlisting}[style=adamshell]
# Backend (FastAPI de la plateforme, le module s'y enregistre)
python -m uvicorn app.api:app --port 8000
#    -> doc interactive http://localhost:8000/docs, routes sous /interview/*

# Frontend
cd frontend
npm install
npm start                          # ng serve sur http://localhost:4200
#    -> page "Simuler un entretien" dans la barre de navigation
\end{lstlisting}

Le module ne demande aucune étape de migration : les tables
\texttt{interview\_sessions} et \texttt{interview\_qa} sont créées à la première
utilisation (\texttt{CREATE TABLE IF NOT EXISTS}, schéma idempotent), dans le même
fichier SQLite que la plateforme, depuis une connexion et un verrou propres.

\subsection{Tests}

\begin{lstlisting}[style=adamshell]
# Suite complete, sans modele ni reseau (HTTP simule)
python -m pytest interview_adam/tests -q

# Avec le vrai plongeur (telecharge les poids all-MiniLM-L6-v2, CPU)

\subsection{Ce que contient \texttt{data/}}

\file{data/\brk} est ignoré par git et renferme, outre la base SQLite de la
plateforme et l'index vectoriel du module, le secret de signature de jetons de
l'hôte. Aucun de ces fichiers n'est versionné, cité en valeur, ni reproduit dans
ce rapport : les journaux cités (§\ref{sec:perf-controle}) ne contiennent que des
durées, des noms de routes et des marqueurs d'état.

\subsection{Compilation de ce rapport}

Deux voies, selon que l'on compile ce chapitre seul ou avec le rapport d'équipe.

\begin{lstlisting}[style=adamshell]
# (a) Chapitre autonome
cd interview_adam/docs/report
pdflatex main && pdflatex main        # deux passes : table des matieres et ref croisees

# (b) Dans le rapport d'equipe, depuis la racine du depot
#   dans le preambule :
#     \newcommand{\adamroot}{interview_adam/docs/report/}
#     \input{\adamroot report-preamble}
#   dans le corps, a l'emplacement du chapitre :
#     \input{\adamroot chapter-interview-adam}
\end{lstlisting}

Le préambule du chapitre ne charge chaque paquet que s'il n'est pas déjà chargé
(\texttt{@ifpackageloaded}) et ne définit aucune colonne de tableau globale : il
n'entre donc pas en conflit avec la mise en page de l'hôte. Il n'utilise ni
\texttt{minted} ni shell---\texttt{escape} : \texttt{pdflatex} suffit, et le
chapitre a été compilé ici avec \texttt{tectonic}~0.17.0, qui met en œuvre le
même moteur.
